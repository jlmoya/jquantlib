## A. Blocked on you — nothing proceeds without a decision

**A1. FMA policy.** `ju_call_one_day` fails at 2.67e-12 relative against TIGHT
and is **the only red test in either port**. Two causes, neither fixable in
isolation: `_M_SQRT_2` computed as `1.0/sqrt(2.0)` double-rounds 1 ULP off
C++'s literal (the same bug is in `normal_distribution.py`, and fixing it alone
regresses `bs_call_otm`), and the oracle `.dylib` is built with clang FMA
contraction — proven by building the same source both ways. Emulating FMAs in
Python would overfit to one build of the oracle.
*Options:* accept a derived per-test bound; rebuild the oracle with
`-ffp-contract=off` and regenerate affected references; or leave it red.

**A2. The LPP3 tolerance — an A2 trigger, arguably A3.**
`HestonExpansionEngine` carries a `5e-4` band for `κ·term < 0.1`, looser than
the `1e-8` floor. The evidence says **the port is closer to truth than C++**:
gap ÷ `|log(K/F)|³` is constant to 1.00–1.02× across all six strikes, collapses
4–5 decades by `κ·term ≈ 0.2`, reaches exactly zero by `κ·term ≥ 1` (a
transcription error does not switch itself off at long maturity), and against a
60-digit evaluation the pinned C++ vol is wrong in its **fourth significant
figure**. Mutation testing still catches an 8.2e-13 relative error in LPP3 `z3`.
*Options:* keep it; or revert `f5600c2` and let those tests fail against C++.

**A3. Phase 6 — release 1.43.0.** The agreed pause point, untouched. Needs your
go-ahead before anything is published to Maven Central or PyPI.

## C. Harness debt

**C1. `cluster_l10b` probe still emits uninitialised-memory denormals.** Three
values in `references/cluster/l10b.json` change every run. Root cause found and
recorded: the probe's market is **degenerate** — `vol_otm_call`/`vol_otm_put`
are exactly 0, so every option price there is mathematically zero and what got
recorded is numerical dust. No test asserts those keys today. **Needs the probe
repaired, not the keys deleted.**

**C2. Probes that fail to compile.** Three inflation probes (constructor
signatures drifted from v1.43) plus the long-standing `cluster_l7d` /
`cluster_l8a`. They are skipped by the `if(EXISTS)` guard, so nothing fails —
which is exactly why they have stayed broken.

**C3. `generate-references.sh` has no orphan-binary guard.** It runs whatever
executables it finds in the build dir. A stale binary with no CMake target, no
source and no git history once corrupted 13 reference keys.

**C4. The union script should carry `foreach` blocks whole.** The
unresolved-variable guard caught it lifting `add_executable(..._${area}_probe)`
out of its loop **three times**. The guard works; the underlying script still
does the wrong thing and relies on the guard to notice.

**C5. Commit-ordering nit (f1).** `harness: register the six probe areas`
landed as commit 5 of 12, so four earlier commits carry probe sources not yet
wired into CMake. Nothing breaks (`if(EXISTS)` guard), but those commits cannot
regenerate their own references in isolation.

## D. Known divergences — recorded, pinned, not fixed

Each is pinned by a test asserting **both** numbers, so none can widen or close
unnoticed.

**PQuantLib**
- `bachelier_black_formula_implied_vol` returns 0 where C++ recovers 0.006.
- A flat moving-reference surface strips flat 0.18 where C++ ranges
  0.181968 → 0.180104. **The interpolator attribution was disproven by the fix;
  the cause is currently unidentified** — recorded as unknown rather than
  guessed.
- `ZeroInflationIndex.fixing` ignores `availability_lag` (2.2e-4 on a CPI quote).
- `LevenbergMarquardt.minimize` omits the C++ cost re-evaluation whose side
  effect leaves the curve on the solution.
- `optionlet_stripper_2` delegates to `scipy.optimize.brentq` despite a ported
  `Brent`.
- `YieldTermStructure` has no `settlement_days` constructor; `check_time_range`
  omits `close_enough(t, maxTime())`.
- The XABR cube's `isAtmCalibrated` dense branch is not ported.
- `mc_double_barrier_engine.py` remaps seed 0 → 1. Matching C++ would make
  seed-0 runs clock-dependent — **a design call, not a mechanical fix**.
- `PiecewiseYieldCurve` silently ignores post-construction quote mutations.
- `InverseCumulativeNormal` omits C++'s Halley refinement (~1e-16/variate).
- `sabr_formula.py` f-strings a float where C++ streams a `Real`: `"1.0 not
  allowed"` vs `"1 not allowed"`. Pinned by asserting **both** strings.
- Three sibling FD engines remain scaffolds raising `NotImplementedError`
  (`FdSimpleExtOUJumpSwingEngine`, `FdSimpleExtOUStorageEngine`,
  `FdSimpleKlugeExtOUVPPEngine`), blocked on `FdmSimple2dExtOUSolver` /
  `FdmSimple3dExtOUJumpSolver`, still stubs. **Their "deferred" note is stale
  for the same reason six others were — they are now cheap.**
- `process_helper` sits on `fd_heston_vanilla_engine.py` where C++ makes it a
  static member of `FdmBlackScholesMesher`. Placement only, not a gap.
- `OvernightIndexedCoupon` implements none of the overnight modifiers.

**JQuantLib**
- **A latent flaky *hang*.** Under load, changing the global evaluation date
  can leave a stale `OISRateHelper` driving an unbounded holiday-skip loop in
  `Calendar.advance`. Not reproducible on demand.
- `ConstNotionalCrossCurrencySwapRateHelper`'s v1.43 rewrite is not ported.
- `GeneralizedHullWhite.LinearFlatInterpolationAdapter` snapshots its endpoint
  ordinates where C++ reads them live — stale `a()`/`sigma()` at `t=0` after
  calibration. Latent; nothing calibrates one today.
- The XABR traits-factories are inconsistent: `Zabr` is ported, its four
  siblings are still allowlisted.
- `InterpolatedDiscountCurve.discountImpl` extrapolates by interpolation.
- `testInterpolateWithoutUpdate` has no Java equivalent by construction (a C++
  SFINAE helper).
