## What this session established

### 1. Two of the ten upstream defect write-ups were WRONG

Full results table: `docs/migration/upstream-verification.md`.

- **Ziggurat** was not "provably unreachable". Off-by-one on the `normF` index:
  `normX` decreasing ⇒ `normF` increasing ⇒ in a wedge `pdf(x) > F(i)`, the
  opposite of the draft's claim. Real figure **1.79% acceptance vs 54.52%**
  correct (~30×). Also: **KS at n=1e6 does not detect it** (D=0.00164 vs
  critical 0.00195), so the draft's suggested KS regression test would not have
  worked either. Fixed + deterministic test, now in PR #2722.
- **assetswap** is not an "unconditional null dereference" — it null-checks
  `arguments` at `:196`. Different, conditional hazard: unchecked
  `dynamic_pointer_cast` at `:206-211` and `:215-221`. **Not fileable as drafted.**

Confirmed as stated: 3, 4, 5, 6, 7, 8, 10. Defect 9 (FdCIR + ModifiedHundsdorfer)
reproduced numerically — diverges for |rho| >= 0.25 and **refining** the time
grid makes it worse (4.72 → -2.7e14 → -2.1e38 → 2.4e81 as tGrid 10→100).

### 4. Repairing l8a will expose a port divergence

PQuantLib's `YearOnYearInflationSwapHelper`
(`termstructures/inflation/inflation_helpers.py:181`) diverges from C++ **at
v1.42.1, not just v1.43**: no `interpolation` parameter, `nominal_yts` optional
where C++ requires it. `set_term_structure` carries an explicit "PQuantLib
divergence" note — it short-circuits the full YYIIS build to
`yoy_rate(maturity - lag)`. A correctly-built probe will emit values the port
may not reproduce.

Also: `CPI::AsIndex` is deprecated in the current tree ("Use either Linear or
Flat"), so repairing these probes means choosing an interpolation explicitly,
and that choice moves the numbers.

### 5. Port re-baselining — the ziggurat fix is NOT in either port

Both ports reproduce the bug verbatim, deliberately, with comments saying so:
JQuantLib `ZigguratGaussianRng.java:238` (note at `:54-58`), PQuantLib
`ziggurat_gaussian_rng.py:100` (note at `:19-21`).

Cost is asymmetric:
- **JQuantLib** pins nothing — no ziggurat probe or reference; only a loose
  moment test that passes either way. Fixing is nearly free.
- **PQuantLib** pins an exact **draw sequence** in
  `references/v143/math/randomnumbers.json` → `ziggurat_gaussian_rng`. Fixing
  the port breaks it, and regenerating requires the oracle to move.

Oracle pin: `migration-harness/cpp/quantlib` @ `v1.43` / `6b57206e0`.
