# Work plan — closing out the v1.43 migration

**Starting point.** Both ports report `0 unflagged / 100.0%`. Java `145d7ea6`,
3850 tests / 0 failures. Python `2ad571a`, 16316 passing / 1 known failure.
Both pushed. What remains is not coverage — it is *trustworthiness of the
evidence*, a backlog of recorded divergences, and the release.

---

## Why this order

Three things drive the sequencing, and they are not the same as "biggest first".

**1. The harness is the foundation, and it is the least trustworthy thing we
have.** Every cross-validated number in both ports is only as good as the probe
that produced it. Seven probes were caught emitting uninitialised or
out-of-bounds memory — each exited 0, printed plausible JSON, got committed as
a reference, and was pinned by a passing test. One test silently reproduced the
wrong scenario entirely and still passed. We only found those seven by
accident, and only after the references were committed. **Nothing else should
be verified until the verifier is verified**, and this is also the cheapest
block of work in the list.

**2. The single most productive thing to distrust is a "blocked" note.** Six
separate times, a recorded blocker turned out to be a claim with an expiry date
that nobody re-checked — `FittedBondDiscountCurve`, `HestonSLVFDMModel` /
`LogEntry`, the multi-D FDM framework, `ExtendedOrnsteinUhlenbeckProcess::
expectation`, `NullPayoff`, `Cube` / `PrivateObserver`. Every one was found by
accident while doing something else. A *deliberate* sweep is likely to yield
more than working the known-divergence list, and it is mostly reading.

**3. Two decisions gate the release but block nothing else**, so they run as a
parallel track rather than a phase.

## Phase 1 — Harness integrity  *(everything else depends on this)*

**Goal:** every reference in both repos is reproducible from a committed probe,
byte-for-byte, and the tooling makes the failure modes we hit impossible rather
than merely unlikely.

1. **Repair the `cluster_l10b` probe.** Its market is degenerate —
   `vol_otm_call`/`vol_otm_put` are exactly 0, so the recorded option prices are
   numerical dust. Fix the market so it measures something, or delete the block
   with a stated reason. Do not just remove the keys.
2. **Fix the five probes that have never compiled** — three inflation probes
   (v1.43 constructor drift) plus `cluster_l7d` and `cluster_l8a`. They are
   skipped by the `if(EXISTS)` guard, which is exactly why they stayed broken.
3. **Add an orphan-binary guard to `generate-references.sh`.** It currently runs
   whatever executables it finds. A stale binary with no CMake target, no source
   and no git history once corrupted 13 reference keys.
4. **Fix the union script to carry `foreach` blocks whole.** The
   unresolved-variable guard caught it three times; the guard works, the script
   still does the wrong thing and relies on being noticed.
5. **Full re-verification.** Rebuild every probe from committed sources, run the
   determinism sweep at N=3, and diff every regenerated reference against the
   committed one. **This is the real deliverable** — it converts "we believe the
   references are sound" into "we checked".
6. **Wire the determinism sweep into CI** so this cannot regress.

**Done when:** all probes compile; the sweep reports 0 non-deterministic; every
committed reference matches a fresh run byte-for-byte; CI enforces it.

## Phase 2 — The stale-premise sweep  *(highest expected yield)*

**Goal:** stop finding these by accident.

1. **Enumerate every deferral comment** in both ports — `deferred`, `blocked`,
   `not ported`, `carve-out`, `not yet`, `Phase N`, `TODO`, `for now`,
   `pquantlib has no`, `Java can't` — and every `NotImplementedError` /
   `LibraryException("not implemented")`.
2. **Verify each premise against the current tree**, not against when it was
   written. The question is only: *is the thing it says is missing still
   missing?*
3. **Fix the cheap ones immediately.** Already known to be in this bucket: the
   three FD engine scaffolds (`FdSimpleExtOUJumpSwingEngine`,
   `FdSimpleExtOUStorageEngine`, `FdSimpleKlugeExtOUVPPEngine`) whose blocker —
   `FdmSimple2dExtOUSolver` / `FdmSimple3dExtOUJumpSolver` — is stale for the
   same reason six others were.
4. **Rewrite or delete every comment whose premise has expired.** A stale
   justification is worse than none: it actively discourages the next reader
   from checking.
5. **Add a lint rule** requiring any new deferral comment to cite the C++
   file:line it is deferring, so the premise is checkable by construction.

**Done when:** every deferral note in both ports is either true today or gone.

## Phase 4 — Recorded divergences

Work the ~20 pinned divergences. Each is already pinned by a test asserting
**both** numbers, so none can widen or close unnoticed — which is why this
comes after Phases 1–3 rather than first.

**Order within the phase, by risk:**

1. **The Java flaky hang** — stale `OISRateHelper` on the global evaluation date
   driving an unbounded holiday-skip loop in `Calendar.advance`. It is the only
   item that can wedge a build, and it is not reproducible on demand, so it
   needs instrumentation rather than a guess.
2. **The unexplained one** — a flat moving-reference surface strips flat 0.18
   where C++ ranges 0.181968 → 0.180104. The interpolator attribution was
   *disproven*, so the cause is currently unknown. Unknown beats mis-attributed,
   but it should not stay unknown.
3. **Correctness-affecting:** `bachelier_black_formula_implied_vol` returning 0
   where C++ recovers 0.006; `ZeroInflationIndex.fixing` ignoring
   `availability_lag`; `LevenbergMarquardt.minimize` omitting the C++
   cost-re-evaluation side effect; `InterpolatedDiscountCurve.discountImpl`
   extrapolating by interpolation.
4. **Remaining scipy delegations** — `optionlet_stripper_2` → `scipy.optimize.
   brentq` despite a ported `Brent`; `InverseCumulativeNormal` missing C++'s
   Halley refinement. **This is the defect family that produced every worst
   finding in the programme**, including the Gauss quadrature that priced an ATM
   Heston call at 1.07e+72.
5. **Design calls needing a decision, not a fix:** the seed 0 → 1 remaps
   (matching C++ makes seed-0 runs clock-dependent).
6. **Cosmetic/placement:** `process_helper` location, the XABR traits-factory
   inconsistency, `sabr_formula` float formatting.

## Sequencing summary

```
Track 0 (you) ─────────────────────────────────────────────► gates Phase 7
                    │
                    └── if "rebuild oracle", feeds Phase 1

Phase 1  harness integrity        ← everything below trusts this
   ↓
Phase 2  stale-premise sweep      ← highest yield, mostly reading
   ↓
Phase 3  test-coverage debt       ← 592 keys already paid for
   ↓
Phase 4  recorded divergences     ← by risk, flaky hang first
   ↓
Phase 5  documentation
   ↓
Phase 6  Dependabot               ← can start any time
   ↓
Phase 7  release
```

**Phases 1–3 are where the real risk reduction is.** Phase 4 is a known,
bounded, pinned backlog; Phase 5 is bookkeeping. If time were short, I would do
1, 2 and 3 properly and ship with Phase 4 documented — which is roughly the
posture we are in today, except that Phases 1–3 have not been done.

**One caution.** Phases 2 and 3 will almost certainly *find* work rather than
just complete it — that has been true of every sweep in this programme. I would
plan for the backlog to grow during Phase 2 before it shrinks, and treat a
Phase 2 that finds nothing as evidence the sweep was too narrow, not as good
news.
